# 项目介绍

`sensor-node-fw` 是 STM32F103RCT6 上的传感器节点固件骨架：以 STM32CubeMX 生成的 HAL 工程为基础，移植 **QP/C 6.9.1（QV 协作式内核）**。当前运行 `AO_Node`、`AO_Sensor`、`AO_Heartbeat`、`AO_Ble`、`AO_Modem`、`AO_Store` 六个活动对象（BLE/4G/存储分别受各自的 `ENABLE` 开关控制；2026-09-20 起 BLE(VG6328) 与 4G(MN316) 都已接上并在跑，2026-09-27 起参数掉电保存在 I2C EEPROM 上），演示 AT 调试通道、1 Hz 仿真采样、滤波/组帧自检、异步心跳日志、BLE/4G 可移植通信组件与参数存储。

> [!info] 当前成熟度
> 这是**可运行的骨架**，不是产品固件。当前传感器数据来自仿真驱动；真实器件接入、产品通信协议、Bootloader/OTA 尚未实现。**参数存储已经可用**：BLE 的 7 个身份参数（SN/名称/PIN/UUID/设备名/型号/批次）可以通过调试口读写并掉电保存。

## 硬件平台

| 项目 | 内容 |
|---|---|
| MCU | STM32F103RCT6（LQFP64，Cortex-M3） |
| 主频 | 72 MHz（HSE 8 MHz 经 PLL ×9） |
| Flash / RAM | 256 KB / 48 KB |
| 调试口 | SWD（`PA13` SWDIO / `PA14` SWCLK） |
| 调试串口 | USART1，`PA9`(TX) / `PA10`(RX)，115200 8N1 |
| 业务串口 | USART2 `PA2`/`PA3` = **BLE 模组（VG6328）**；USART3 `PB10`/`PB11` = **4G 模组**（2026-09-20 对调，见 [[03-资源分配#引脚分配]]） |
| BLE 控制脚 | `PB1`(`VG6_EN`) 电源使能（高开启，BSP 拉高）；`PB0`(`VG6_IO`) 唤醒，当前悬空 |
| 板卡 | CubeMX 中标记为 `board=custom`（自定义板，无对应官方评估板） |
| 参数存储 | `AT24C04`（4 Kbit / 512 B）挂在 `I2C1`：`PB6`=SCL、`PB7`=SDA，100 kHz，7 位地址 `0x50` |

引脚与时钟的完整分配见 [[03-资源分配]]。

## 目录结构

```
sensor-node-fw/
├── sensor-node-fw.ioc        CubeMX 工程配置（唯一配置源）
├── Core/                     CubeMX 生成：启动、时钟、GPIO、USART、中断
│   ├── Inc/                  main.h gpio.h usart.h stm32f1xx_it.h stm32f1xx_hal_conf.h
│   └── Src/                  main.c gpio.c usart.c stm32f1xx_it.c
│                             stm32f1xx_hal_msp.c stm32f1xx_hal_timebase_tim.c
│                             system_stm32f1xx.c
├── App/                      自研代码（不参与 CubeMX 重新生成）
│   ├── app/                  装配点、全局配置、六个 AO（node/sensor/heartbeat/ble/modem/store）
│   ├── service/              AT 解析、日志、滤波、CRC-16、参数记录编解码
│   ├── driver/               传感器统一接口（仿真源）、AT24C04 非阻塞驱动
│   ├── bsp/                  QP 钩子、时基、USART1 收发、BLE/4G 端口、I2C1 主机
│   └── tools/                工程修补与烟测脚本
├── ThirdParty/               外部库登记区（当前为空）
├── Qpc/                      QP/C 框架
│   ├── platform/             与平台无关的框架源码（QEP / QF / QV）
│   └── port/qv/              QV 内核到 Cortex-M 与 ARM-Keil 的移植
├── Drivers/                  CMSIS + STM32F1xx HAL（生成代码）
└── MDK-ARM/                  Keil 工程与构建产物
    ├── sensor-node-fw.uvprojx
    └── sensor-node-fw/       输出目录（.axf / .hex / .map / 构建日志）
```

> [!tip] 生成代码与手写代码的边界
> `Core/` 与 `Drivers/` 由 CubeMX 生成，任何改动必须写在 `/* USER CODE BEGIN */` 与 `/* USER CODE END */` 之间，否则重新生成时会被覆盖。业务代码一律放 `App/`，自行管理。分层关系见 [[02-程序框架]]。

## 快速开始

1. 用 Keil MDK 打开 `MDK-ARM/sensor-node-fw.uvprojx`
2. 确认已安装器件包 `Keil.STM32F1xx_DFP 2.4.1`，目标选择 `sensor-node-fw`
3. 全编译应得到 `0 Error(s), 0 Warning(s)`，产物在 `MDK-ARM/sensor-node-fw/`（`.axf` / `.hex` / `.map`）
4. 通过 SWD 下载（工程内已配置下载算法）；也可以拿生成的 `.hex` 用 STM32CubeProgrammer 独立烧录
5. 用 USB-TTL 连接 `PA9` / `PA10`，串口参数 **115200 8N1，无流控**（见 [[06-协议格式#物理层]]）
6. 复位后观察启动横幅与自动采样；发送 `AT`（以 CR/LF 结束）应收到 `OK`

复位后的关键输出如下（构建日期与复位原因以实机为准）：

```
==== sensor-node-fw ====
ver    : 0.3.0  (built <date/time>)
target : STM32F103RCT6  72 MHz  flash 256K/ram 48K
kernel : QP/C 6.9.1  QV (cooperative, single stack)
reset  : <cause>
chan   : USART1 115200 8N1  (debug/AT only)
i2c    : I2C1 PB6/PB7 100000 Hz  (param store)
------------------------
at console ready (line-based AT, CR/LF terminated)
params : AT+SN? read | AT+SN="<v>" write | AT+SN=? max len
names  : SN NAME PIN UUID DEVNAME MODEL BATCH
store  : AT+CFG? status | AT&F defaults | AT+I2C? scan
actors : node p1 | sensor p2 | heartbeat p3 | ble p4 | modem p5 | store p6
boot ok
```

随后 `AO_Sensor` 每秒输出一行仿真采样，`AO_Heartbeat` 每 2 秒输出异步日志，`AO_Ble` / `AO_Modem` 在进入各自状态时打印一行它们占用的串口：

```
sensor> #1 t=<温度>C rh=<湿度>% frame=10B selfcheck=SVC_OK
[I <ms>] heartbeat: alive, t=2 s
[I <ms>] ble: VG6328 on USART2 115200 8N1, waiting for module startup
[I <ms>] modem: MN316 on USART3 9600 8N1, waiting for module startup
```

上板时**先核对 `ble:` / `modem:` 那两行的实例与波特率**——它们直接反映 `APP_CFG_BLE_UART_ID` / `APP_CFG_BLE_UART_BAUD` / `APP_CFG_MODEM_UART_ID` / `APP_CFG_MODEM_UART_BAUD` 有没有按接线配好，是「固件是否占用了预期那一路串口」的第一手证据。

`AO_Sensor` 初始进入 `Idle` 时打印的 `sensor> idle` 原先带 `(send 's' to start sampling)` 提示，而 `s` 指令早已删除；该误导性文案已在 2026-09-20 清理，采样仍由装配点投递的 `SYS_SENSOR_START_SIG` 自动启动。

## 构建尺寸

> [!warning] Keil（L1）口径待回填，本节原先的表格已删除
> 本节原挂的是**旧骨架**（三 AO、无组件层）的 Keil 数据（Code 12814 / Flash 13524 / RAM 2144），与当前镜像相差一个数量级，2026-09-20 已删除以免误导。当前可用的口径是 GCC L2 烟测：
>
> | 配置 | text | data | bss | Flash | RAM |
> |---|---|---|---|---|---|
> | BLE + 4G(MN316) 均开（2026-09-20 发布态） | 97594 | 1752 | 14412 | 99346 B ≈ 37.9% | 16164 B ≈ 32.9% |
> | 只开 BLE（`APP_CFG_MODEM_ENABLE=0`） | 94682 | 1752 | 8356 | 96434 B ≈ 36.8% | 10108 B ≈ 20.6% |
>
> 两口径不同源不可混用；正式 Flash/RAM 需在有 Keil 的环境用 ARM Compiler 6 全量编译后补回。细节见 [[03-资源分配#内存占用实测]]。
