# 协议格式

## BLE 小程序协议

USART2 连接 VG6328（PA2/PA3，115200 8N1；2026-09-20 与 4G 模组对调，占哪一路由 `APP_CFG_BLE_UART_ID` 决定）。透明通道帧为 2 B 大端载荷长度、最多 17 B 载荷和 CRC8 `0x07`，总长不超过 20 B；长 JSON 以 14 B 数据分片，并携带 1 B 序号和 2 B 总长度。命令为 `auth/params/get/set/ping/nak/reboot`，设备主动发送 `data`；认证成功响应包含 `ok=true` 与 SN，断链立即清除认证和半包状态。

USART1 当前是开发调试通道，承载 AT-only 输入、启动信息、采样诊断和异步日志。它不是具备寻址、确认、重传与帧同步的产品通信协议。

## 物理层

| 项目 | 值 |
|---|---|
| 外设 / 引脚 | USART1；`PA9` TX、`PA10` RX |
| 串口参数 | 115200，8N1，无流控，3.3 V TTL |
| 接收 | 逐字节中断；64 B RX 环形缓冲；`USART1_IRQn` 优先级 5 |
| 同步发送 | `BSP_print*()`，只用于启动信息与少量诊断 |
| 异步发送 | 512 B TX 环形队列，USART1 发送中断搬运；用于日志与 AT 响应 |
| 文本编码 | 运行期字符串全部为 ASCII 英文，行尾统一 `\r\n` |

## AT 输入

解析器在 Service 层 `App/service/svc_at.c`（只解析），统一命令请求与结果模型在
`App/app_command/app_command.h`，命令的**执行与回复**由 App 层
`App/app/command_dispatch.c`（`App_Command_Dispatch()`）负责。参数读写落在
`AO_Store` 上异步完成，因此调试口不会因为写 EEPROM 而卡住。

命令形态按 V.250 / 3GPP 27.007 的常规约定：**`AT` 前缀 + `?` 读 + `=` 写 + `=?` 测试**，
响应是 `OK` / `+<参数名>:"<值>"` / `+<参数名>:(<最大长度>)` / `+CME ERROR:<n>`。

> [!note] 2026-09-27 接口改写：旧的自定义写法已删除
> 改写前的 `at` / `sn?` / `sn=值` / `cfg?` / `cfg!` / `i2c?` **不再兼容**（缺 `AT+` 前缀、
> `!` 不是 AT 语法元素、错误码用自造的 `+err:<n>`、`ok` 大小写也与标准不符）。
> 同一次改写还删掉了「裸 `at` 不带行尾也回 `ok`」的捷径——它会让 `AT+SN?` 的前两个字符
> `AT` 触发误判。**现在所有命令都必须以 CR 或 LF 结尾。**

### 命令一览

| 请求 | 响应 | 说明 |
|---|---|---|
| `AT` | `OK\r\n` | 握手（大小写不敏感，但必须带 CR/LF） |
| `AT+<参数名>?` | `+<参数名>:"<值>"\r\nOK\r\n` | 读**字符串型**参数；值取自 RAM 影子，**不访问总线** |
| `AT+<参数名>?`（数值型） | `+<参数名>:<值>\r\nOK\r\n` | 读**数值型**参数（`TRANSINTVL`）：**值不带引号** |
| `AT+<参数名>="<值>"` | `OK\r\n` | 写参数；立即改内存影子，落盘异步进行。**身份类参数（当前 `SN`）只允许串口写**，云端写回 `+CME ERROR:4`；`SN` 写成功且**值真的变了**时会自动重启（见下） |
| `AT+<参数名>="<值>"`（不带引号） | `OK\r\n` | 引号可省：`AT+SN=VWA2608A0020` 同样受理 |
| `AT+<参数名>=?` | `+<参数名>:(<最大长度>)\r\nOK\r\n` | 测试形式：报告该字段可写的最大字符数（容量 −1） |
| `AT+TRANSINTVL?` | `+TRANSINTVL:<分钟>\r\nOK\r\n` | 查周期上报间隔（分钟，1~20；数值型，不带引号） |
| `AT+TRANSINTVL=<1..20>` | `OK\r\n` | 写周期上报间隔（分钟）：**掉电保存**、**改完立即生效** |
| `AT+VER?` | `+VER:"<版本>","<编译日期>"\r\nOK\r\n` | 查询固件版本与编译日期 |
| `AT+CFG?` | `+CFG:<8 个逗号分隔字段>\r\nOK\r\n` | 参数存储运行状态（**位置式**，见下表） |
| `AT&F` | `OK\r\n` | 全部恢复编译期默认值并落盘（`config_version` 继续自增）。**仅串口**：云端发回 `+CME ERROR:4`（见下） |
| `AT+RST` / `AT+REBOOT` | `OK\r\n` | **重启设备**：先回 `OK`，**延时**（≥500 ms，最多 5 s）后复位，见下 |
| `AT+BLESVCUUID?` | `+BLESVCUUID:"<UUID>"\r\nOK\r\n` | 查 BLE 服务 UUID（= 参数 `uuid`，2026-09-28 新增；**回显名就是命令名**，见下） |
| `AT+I2C?` | 先 `OK\r\n` | 受理 I2C 总线扫描；结果随后以 `+I2C:<地址>` URC 上报，末尾 `+I2C:END` |
| 其他非空行 | `ERROR\r\n` | 收到 CR/LF 后判断，不回显输入 |
| 空行 | 无 | 静默忽略 |
| 非 CR/LF 控制字符 | `ERROR\r\n` | 不解析、不回显 |

参数名（**7 个**，大小写不敏感，响应里统一回大写）：`SN`、`PIN`、`UUID`、`DEVNAME`、`MODEL`、`BATCH`、`TRANSINTVL`。
其中前 6 个是**字符串型**（读回带引号、`=?` 报可写字符数），`TRANSINTVL` 是**数值型**业务参数
（周期上报间隔，分钟，1~20：读回不带引号、`=?` 报范围 `(1,20)`、写越界回 `+CME ERROR:2`）。
参数值区分大小写（SN/名称类身份信息必须原样）。行长度上限由 `APP_CFG_AT_LINE_MAX`（64）决定，
超限的整行会被丢弃并回 `ERROR`（**不是**静默——但现场看起来就是「这条命令没生效」，
因此发长命令时务必确认长度）。

> [!warning] `NAME` 是**退役参数**（2026-09-28）：广播名就是 `SN`
> 产品决定**蓝牙广播名 = 设备 SN**（用户 2026-09-28 确认），因此 `AT+NAME?` / `AT+NAME="…"` /
> `AT+NAME=?` 三种形态一律回 `+CME ERROR:1`（= 没有这个名字），要读广播名请用 `AT+SN?`。
> 参数槽位本身**没有删除**：记录按 id 定位字段，删中间一项会让后续字段整体错位、介质里的
> 旧记录被解码到错误字段上（见 `App/service/svc_param.h` 的退役槽位 NOTE）。
> 判据在 `SVC_Param_IsRetired()`，命令层在读写测试三处统一挡掉。

> [!important] 写权限：**身份类参数只允许串口写**（2026-09-28）
> 当前身份类参数有**两个**：
> - `SN` —— 平台 MQTT 主题里的 `deviceId` + 蓝牙认证应答里的 `sn`；
> - `UUID` —— BLE 服务 UUID，**每台唯一**，启动时写进 VG6328，手机小程序靠它认设备。
>
> 它们都是「产线写一次、之后不该被远程改」的东西，因此按**来源**分权：
> | 通道 | 读（`AT+SN?` / `AT+BLESVCUUID?`） | 写（`AT+SN="…"` / `AT+UUID="…"`） |
> |---|---|---|
> | 串口 | ✅ | ✅（产线唯一入口） |
> | 云端（4G `command` 主题） | ✅ | ❌ 回 `+CME ERROR:4` |
> | 蓝牙小程序 | ✅（认证应答里的 `sn` 字段） | ❌ 本来就不支持写参数 |
>
> 判定在 `App/app/command_dispatch.c` 的 `writeAllowedFrom()`，身份类参数列在 `kIdentityParams[]` 里；
> 加新的身份参数（如 `BATCH`）只需往那张表补一个 id（**写入权限、变更判定与自动重启三处会一起生效**）。
> **为什么这么严**：身份写错是**静默故障**——`SN` 错一个字符，`+MQTTSUBACK` 照样返回、
> 平台一条命令都收不到（本仓库已踩过一次，见 [[08-改动日志]] `#51`）；
> 而云端一旦被误操作/盗用就能**批量改掉设备身份**。
>
> NOTE (身份类 ≠ 设备号类)：**只有 `SN`** 还要过一道"值校验"（字符集/长度/出厂哨兵，
> 因为它的值会嵌进 MQTT 主题）；`UUID` 不套那套规则——它的默认值就是合法值，
> 拿设备号判据去查会被误判成"产线没刷"而拒写。两者的分工见 `isIdentityParam()` 与 `isDeviceIdParam()`。
>
> **写成功后会自己重启**（2026-09-28）：`AT+SN="新值"` / `AT+UUID="新值"` 且**值真的变了**时，
> 固件会请求一次复位——由 `AO_System` 延时执行（先等参数落盘、再复位，见 [[04-任务调度]]），
> 串口上依次出现：
>
> ```text
> system: reboot requested by identity, waiting for reply+store
> system: rebooting now, src=identity waited=612 ms
> ```
>
> - **写回原值（值没变）不会重启**，所以产线脚本可以重复跑；
> - **为什么不立刻复位**：`OK` 只是「已受理」，参数还在异步落盘；立刻复位会让新 SN 丢掉；
> - **为什么必须重启**：`SN` 是设备身份（`deviceId`）。MQTT 的 `clientId` 与全部主题是
>   连接计划启动时拼好的，只改内存不会重新订阅，设备会停在「旧身份」的世界里；
>   蓝牙侧也有已认证的会话需要作废。
>
> **值也有闸**：写入侧 `SVC_Param_IsValidDeviceId()` 会拒掉空值、含 `/` `+` `#` 空格等
> 非法字符、以及**仍等于出厂默认值**（= 产线没刷）的写法，统一回 `+CME ERROR:2`；
> 启动侧用同一个函数判，不合法就**拒绝启动 4G**（详见下面的「设备标识」一节）。

> [!warning] `AT+RST` 是**延时复位**，不是"回完就立刻重启"
> 两个拼写等价：`AT+RST`（平台规则文档里的名字）与 `AT+REBOOT`（本工程自己的叫法，与 BLE 侧一致）。
> 只认**裸命令**——`AT+RST=1`、`AT+REBOOT?` 都不受理（会走普通的 SET/TEST 分支回错误码）。
>
> 收到命令后设备**先回 `OK`**，然后在满足下面三个条件后复位（由 `AO_System` 执行，见 [[04-任务调度]]）：
> ① 至少过了 `APP_CFG_SYSTEM_REBOOT_MIN_DELAY_MS`（500 ms）；
> ② 参数已经落盘（`App_Store_IsIdle()`）；
> ③ 上行的 `command/reply` 已经发出去（`Modem_IsUplinkIdle()`）。
> 若 5 s（`APP_CFG_SYSTEM_REBOOT_MAX_WAIT_MS`）内条件仍不满足，**到点照样复位**。
>
> **为什么必须这样**：复位会丢掉 UART 发送环里的字节、打断 EEPROM 写入、掐断还没发出去的
> MQTT PUBLISH。就地复位会让「平台判指令超时 + 串口无输出 + 刚改的参数丢失」三件事同时发生，
> 而设备已经重启，两边现象对不上——是最难查的一类现场。
>
> 上板可见的证据（串口，复位前最后几行）：
> ```text
> [W 123456] system: reboot requested by cloud, waiting for reply+store
> OK
> [W 124068] system: rebooting now, src=cloud waited=612 ms
> ```
> 复位后启动横幅的 `reset` 行会显示 `SOFT (software reset)`。

> [!note] 平台（4G）侧的命令现状
> - **已实现**：`AT`、`AT+VER?`、`AT+CMD?`（返回本设备命令表，当前是 `+CAD:…` 格式）、
>   `AT+<参数名>?` / `="<值>"` / `=?`、`AT+TRANSINTVL?` / `AT+TRANSINTVL=<1..20>`、
>   `AT+CFG?`、`AT+I2C?`、**`AT+RST`**（重启设备，回 `OK` 后延时复位）。
> - **云端不可用**（2026-09-29 收紧）：`AT&F` —— 回 `+CME ERROR:4`。它重置**全部**参数（含 `SN`），
>   云端可执行等于一条命令把设备"变砖"：`SN` 变回出厂默认 → 设备主动停 4G → 只能串口救。
> - **未实现**：「设置上报主题」与 `AT+GMR` / `AT+GSLP`，收到回失败应答
>   （`ok:false` + `error:"ERROR"`，见 [[11-平台接口需求]] 1.4）。
>
> ⚠️ 已知不一致（待办，2026-09-29 记录）：`+CAD` 能力清单里把"查命令表"这条写成了 `AT+CAD?`，
> 而解析器只认 **`AT+CMD?`**（本页与串口帮助行也都是 `AT+CMD?`）。平台若照清单发 `AT+CAD?` 会收到
> `+CME ERROR:1`。见 [[08-改动日志]] `#81` 遗留 —— 修法是一处字符串，等平台侧确认后再动。
>
> 需求与待平台确认项见 [[11-平台接口需求]]。

### 错误码

| 响应 | 触发条件 |
|---|---|
| `ERROR\r\n` | 命令不认识：缺 `AT` 前缀、参数名/命令名拼错、`=` 后面是空值 |
| `+CME ERROR:1\r\n` | 参数名不在 7 个之列（读写与测试形式都适用）；**退役参数 `NAME` 同此码** |
| `+CME ERROR:2\r\n` | 值为空或超长（超过了该字段的容量）；或**数值型参数越界**（`AT+TRANSINTVL=0` / `=21`） |
| `+CME ERROR:3\r\n` | 参数存储还没就绪（上电加载未结束，此时改会被随后的读取覆盖）；`AT&F` 同理 |
| `+CME ERROR:4\r\n` | **该来源无权写这条参数**：身份类参数（当前 `SN`）只允许串口写，云端写回这个码，且**不写进影子**；**`AT&F` 同此档**（它会连 `SN` 一起重置，云端可执行等于一条命令把设备"变砖"，见下） |
| `+CME ERROR:5\r\n` | `AT+I2C?`：已有扫描在跑，或存储未就绪 / 已关闭 |

> [!warning] `OK` 只代表「已受理」，不代表「已写进 EEPROM」
> 写参数是先改内存、再由 `AO_Store` 异步落盘。真正的结果看日志：
> `store: saved ver=<版本> seq=<槽序号> slot=<A|B> <字节数> B` 表示落盘并**回读校验**通过；
> `store: save failed (...), change kept in RAM only` 表示这次修改只在内存里，掉电会丢。

### `AT+CFG?` 字段含义

响应是**位置式**逗号分隔，顺序固定（只允许在表尾追加新字段）：

```text
+CFG:rdy,present,loaded,dirty,ver,seq,ok,fail
OK
```

> [!note] 读/测试/`AT+CFG?`/`AT+VER?` 的响应都以最终 `OK` 收尾
> 2026-09-27 起，除写命令外，查询类响应也在参数行之后补一行 `OK\r\n`（见 [[08-改动日志]] `#47`）。
> 目的是让串口与 4G 共用同一串 AT 文本：串口原样打印，4G 直接把它当 `data` 包进 `command/reply`。

| 位置 | 字段 | 含义 |
|---:|---|---|
| 1 | `rdy` | 启动加载阶段是否已结束（0 时所有写命令都回 `+CME ERROR:3`） |
| 2 | `present` | 介质是否应答过 —— 当前是 SPI NOR，判据是 **JEDEC ID 探测成功**（`EF 40 16`）；0 = 芯片不在 / SPI 不通 / 片选不对 |
| 3 | `loaded` | 当前值是否来自介质上的**有效记录**（0 = 用的是编译期默认值） |
| 4 | `dirty` | 有改动还没落盘 |
| 5 | `ver` | `config_version`，每次成功保存自增 |
| 6 | `seq` | 最近一次保存写入的槽序号（每次保存 +1，用于在多个快照之间定序） |
| 7 / 8 | `ok` / `fail` | 成功保存次数 / 失败次数（诊断） |

单字符命令 `g/h/s/x/d/?` 已删除。采样由 `App_start()` 在上电时自动启动，不通过调试命令控制。

## 4G 下行命令（平台 `command` 主题）

本轮按用户确认的 [[13-寄存器表与读写命令]] 接入新 JSON 命令格式。当前固件支持 `AT`、`AT+RST`、`AT+READ`、`AT+WRITE`；串口保留既有产线诊断命令，云端不再开放完整诊断命令集。

### 主题与设备标识

2026-10-14实机与本地MN316 MQTT手册§2.11/§3.2核对：`+MQTTPUBACK:6,0` 是QoS1发布收到服务器确认的通知，6为MQTT消息包ID，0为dup非重发标志，1为重发。当前测量上报QoS0、命令回复QoS1，具体归属须结合前一条发布主题判断。当前固件仍用发布命令的OK结束发送调用，未将PUBACK包ID与应用请求关联；Broker确认不等于平台业务处理完成，不能直接据此删除未来Flash历史队列。旧“MN316没有PUBACK”的说明是事实性错误，见 [[08-改动日志]] #135。

当前 `app_config.h` 的十个 `APP_CFG_MODEM_TOPIC_PREFIX_*` 均为 `"/"`，每条仍独立配置。新接口使用：

| 主题 | 方向 / QoS |
|---|---|
| `/<productId>/<SN>/properties/report` | 设备发布 / 0 |
| `/<productId>/<SN>/command` | 设备订阅 / 1 |
| `/<productId>/<SN>/command/reply` | 设备发布 / 1 |

`SN` 仍来自 `App_Store_Value(SVC_PARAM_BLE_SN)`，同时决定 MQTT clientId 和主题；最多23个ASCII字母、数字、`-_.`，出厂哨兵值不可上线。串口修改身份参数后仍走存储完成再复位流程。此前不带前导斜杠及旧外壳的实测仅代表历史版本，不能作为新接口的联调结果，记录见 [[08-改动日志]] #64、#77、#132。

### 请求与回复

写上报周期5分钟：

```json
{"id":"cmd-write-001","command":"AT+WRITE","data":"01,0005,65FC"}
{"id":"cmd-write-001","data":"01,00,BF25"}
```

读取倾角，有有效0.02°数据时：

```json
{"id":"cmd-read-001","command":"AT+READ","data":"10,1434"}
{"id":"cmd-read-001","data":"10,0002,352F"}
```

`352F` 按实际 `10,0002` ASCII计算。读写回复仅含 `id/data`，不带 `ok/error/command`、AT前缀、换行或最终结果行。帧错误返回 `data:"+CME ERROR:2"`（结构）或 `data:"+CME ERROR:6"`（CRC），不执行任何写入、不附CRC。逐地址失败返回读 `XX/XY`、写 `RO/OV/IC/NP/SE/XY`；成功写结果为 `00`。混合结果的CRC包含字母标记。

基础指令无 `data`、无CRC，回复回显 `command`：

```json
{"id":"at-001","command":"AT"}
{"id":"at-001","command":"AT","data":"OK\r\n"}
```

`AT+RST` 仍由统一命令分发投递延迟复位事件，先排队应答并等待上行与Store空闲。零点标定暂未接入，本轮收到 `AT+ZERO="CONFIRM"` 返回 `ERROR\r\n`，不改变测量基准。

### 本轮寄存器范围

| 地址 | 当前行为 |
|---|---|
| `01` | 读写1～20分钟，复用统一周期与Store异步保存 |
| `02/03` | 可读当前编译期模式3/默认掩码000F；非法值OV，合法写入NP，等待运行控制与持久化接入 |
| `10～17` | 只读倾角、温度、电压、三轴加速度；使用最近一次完成批次，首次无样本/本批失败返回XX |
| `20` | 只读固件主×100＋次，当前0.3.0读0003 |
| `40～4B` | 只读SN，高字节ASCII在前，NUL补齐 |
| `50～55` | 只读UUID12字符末段，平台一次读取六格并追加固定前缀；不符合固定前缀/长度的影子返回XX |
| 未分配 | XY，不作为有效寄存器 |

电压有效性独立于倾角；批次失败后禁止返回前一批倾角。负值按16位补码编码，超出s16或倾角±18000范围返回XX。2026-10-14负倾角换算已在滤波前修正为16位补码，过零不再产生约360/90°假跳变；主机测试通过，上板L5待验证，见改动日志#134。`01` 的 `00` 表示影子更新和异步保存已受理，不代表Flash提交已完成；断电保持需等 `store: saved` 再验证。02/03、零点、上传选择、上报加速度、RTC/timestamp和Flash历史补传属于后续阶段，对外目标协议仍见13。

### 长度、执行顺序与邮箱

`id` 最多63字符，`command` 缓冲96字节，寄存器 `data` 最多52字符，读回复最多132字符；地址2位、数值4位、CRC4位大写hex。先验证整条结构和CRC，再按顺序逐项执行，最多读16项/写6对；部分写成功不回滚，重复地址按请求顺序返回。

JSON解析拒绝重复/未知字段、非字符串值、超长字段、尾随内容、非法转义和字符串内控制字符；允许字段重排和可打印ASCII Unicode转义。不得截断后执行。串口仍用 `AT+READ="..."` / `AT+WRITE="..."`，成功回 `+READ/+WRITE` 与最终 `OK`，逐项失败最后为 `ERROR`；超长整行拒绝。

平台应在同一设备上一条应答到达或超时后再下发下一条。单邮箱已有请求、排队应答或应答在途时，新增下行不执行，保留原请求/应答；旧属性主题也遵守该保护。此阶段尚无关联ID去重缓存，不可据此宣称一次且仅一次执行。

## 参数存储（SPI NOR）

调试口读写的 **7 个**参数都掉电保存在 **SPI NOR（W25Q32JVSNIQ，4 MiB）** 上：前 6 个是 BLE 身份配置，
第 7 个 `transintvl` 是**设备业务参数**（周期上报间隔）。表里另有一个**已退役**的槽位：

> [!note] 2026-09-30 换介质
> 原 **I2C EEPROM（AT24C04）** 路径已停用：参数介质改为 `SPI1` + `W25Q32JVSNIQ`
> （`PA5`/`PA6`/`PA7` + 软件片选 `PA8`）。`drv_at24c04` / `bsp_i2c` / `APP_CFG_STORE_I2C_*`
> 宏与 `AT+I2C?` 诊断**仍在树里**，是否退役待定（见 [[08-改动日志]] `#86`）。

| 参数名 | 对应宏（默认值） | 容量 | 说明 |
|---|---|---:|---|
| `sn` | `APP_CFG_BLE_SN` | 24 | **设备序列号**：MQTT `deviceId` + 蓝牙认证应答的 `sn` + **蓝牙广播名**（三者同一个值） |
| ~~`name`~~ | —（随 `SN`） | 24 | **已退役**（2026-09-28）：广播名已并入 `SN`，本名字对外不存在（回 `+CME ERROR:1`）；槽位保留仅为介质兼容 |
| `pin` | `APP_CFG_BLE_PIN` | 12 | 小程序认证 PIN（凭据，日志不打印） |

| `devname` | `APP_CFG_BLE_DEVICE_NAME` | 24 | 设备名（`device_info` 应答里的 `deviceName`） |
| `model` | `APP_CFG_BLE_MODEL_CODE` | 16 | 型号代号 |
| `batch` | `APP_CFG_BLE_BATCH_CODE` | 16 | 批次代号 |
| `transintvl` | `APP_CFG_MODEM_TRANS_INTERVAL_DEFAULT_TEXT` | 4 | **周期上报间隔**，分钟，1~20（数值型） |

> [!note] `transintvl` 与旧的云属性 `sample_interval`
> 设备**实际上报周期**只由 `transintvl` 决定（`AO_Modem` 每个 Process 周期从参数影子读一次，
> 见 `App/app/modem.c` 的 `reportIntervalMin()`），因此改完**立即生效**且掉电保持。
> 4G 组件里那份旧的云属性 `sample_interval`（1~1440 分钟、仅 RAM）**不再驱动上报节奏**，

记录格式与 CRC 见 `App/service/svc_param.h` 的文件头；**掉电提交与扇区轮换**见
`App/service/svc_config_journal.h`（一槽 256 B = 16 B 外层头 + 原记录 + `FF` 填充 + 尾部 4 B 提交标记；
**只在另一个扇区已有有效副本时才回收**，作业失败不擦最新副本）。`app_config.h` 里的宏只作为
**首次上电（介质空白或损坏）时的默认值**；只要介质上有一份 CRC 正确的记录，就以它为准。

启动横幅由 BSP 打印硬件与内核信息，App 在各 AO 启动后打印 AO 列表和 `boot ok`。构建时间和复位原因按实际运行变化；`actors` 行按编译期开关列出真正启动的 AO（2026-09-27 起含 `store p6`）。

==== sensor-node-fw ====

target : STM32F103RCT6  72 MHz  flash 256K/ram 48K
kernel : QP/C 6.9.1  QV (cooperative, single stack)
reset  : <cause>
chan   : USART1 115200 8N1  (debug/AT only)
i2c    : I2C1 PB6/PB7 100000 Hz  (param store)
------------------------
at console ready (line-based AT, CR/LF terminated)
params : AT+SN? read | AT+SN="<v>" write | AT+SN=? max len

发送终态输出（示例数据，不代表硬件实测）：

```text
cloud> sent {"deviceId":"sftest0004","properties":{"temperature":25.09,"angle_x":1.37,"angle_y":0.25,"angle_z":88.59,"signal_quality":15,"battery_voltage":3.670}}
ble> sent {"cmd":"data","seq":1,"angle_x":1.37,"temperature":25.09,"angle_y":0.25,"angle_z":88.59,"signal_quality":15,"sample_interval":2,"voltage":3670}
[W <ms>] modem: publish failed reason=<code>
[W <ms>] sensor: sample failed reason=scl3300 drv=<code> ready=<0|1> count=<n> elapsed=<ms> ms
[D <ms>] 4g-core: +MQTTTO:5
[D <ms>] 4g-core: session check state=3 -> rebuild
```

在线期会话诊断（2026-10-14，`#138`）：`4g-core: +MQTTTO:<type>` 是模组自己的 URC 透传（手册 MQTT 用户手册 §2.9/§2.11，**type=5 = ping 超时**：PINGREQ 没等到 PINGRESP）。收到这类通知或在线期看到 `+CME ERROR:8002` 时，组件会**先复核会话**并打印一行 `session check state=N -> keep|rebuild`（`N` 是模组报的 `+MQTTSTAT` 状态，`5` = 已连接；`keep` 保留链路、`rebuild` 判失效让 AO 整条重建并重新订阅）。`4g-core: +MQTTREC:n`（模组自己在重连）与 `+MQTTDISC:OK` 不经复核，直接判失效。

4G输出条件是模组发布命令的成功终态（MN316为`OK`），打印同一份冻结的实际发送JSON；不代表平台业务确认。失败只输出原因，不打印这次测量。BLE输出表示整份数据帧已交给UART发送队列，不代表手机ACK。诊断日志仍受日志级别控制，AT输入/响应格式保持原样。

采样失败行的字段（2026-10-14 加，用于区分同一句话背后的四类故障）：`drv` 是 `drv_status_t` 数值——`2`=`DRV_ERR_BUS`（驱动把「数据帧 CRC 不符 / 器件回 RS≠01 / BSP 事务错（DMA TEIF、OVR、MODF 或单帧 100 ms 超时）」都收敛成这个码），`3`=`DRV_ERR_TIMEOUT`（单次采样作业 1500 ms 超时），`4`=`DRV_ERR_NODEV`（发起时器件未就绪）；`ready` 是失败瞬间器件是否仍处于 `SCL_READY`（`0` 表示已进入 STATUS 读清或重初始化流程）；`count` 是本批已完成的有效采样点数（`0` 表示第一个角度帧就失败）；`elapsed` 是距本批启动的毫秒数，用来对照 1500 ms 与 8000 ms 两级期限。`cycle_timeout`（整批 8000 ms）与 `scl_start`（器件未就绪）同样带这四个字段。

启动时仍有模组配置和参数存储诊断，`i2c`速率来自HAL句柄。BLE默认不广播，初始化ADE=0，按键开启120s窗口。当前没有1Hz `sensor>`行和2s `heartbeat: alive`行，也不输出旧仿真湿度、自检帧或电池原始数据行。传感器是真实SCL3300，角度0.01°、片内温度0.01°C。

连接故障诊断保留`reason/step/rx/tx_ovf/uart_err`；`rx=0`表示没有收到字节，不能仅凭`uart_err=0`排除波特率或接线问题。运行中无需连续日志也能用`AT`检查控制台响应。

## Service 二进制帧

`App/service/svc_frame.{h,c}` 已实现内部组帧与严格解析，当前由 `AO_Sensor` 用于“组帧后立即解析”的自检，尚未直接作为 USART1 产品协议发送。

| 字段 | 长度 | 当前定义 |
|---|---:|---|
| SOF | 2 B | `0xAA 0x55` |
| LEN | 1 B | PAYLOAD 长度 |
| CMD | 1 B | 采样上报为 `0x10` |
| PAYLOAD | N B | 小端；采样载荷为温度 `int32` + 湿度 `uint16`，共 6 B |
| CRC16 | 2 B | CRC-16/MODBUS，初值 `0xFFFF`、多项式 `0xA001`，覆盖 LEN/CMD/PAYLOAD |

解析采用严格长度匹配，失败返回 `SVC_ERR_RANGE`、`SVC_ERR_CRC` 或 `SVC_ERR_NOMEM`。正式产品协议仍需定义地址、命令码全集、应答、超时、重传和重复帧策略。

### 手工最小验证（5 步）

用任意串口助手即可，**每条命令都要带 CR/LF 行尾**（裸 `at` 已不再识别）。

| 步骤 | 发送 | 期望 | 这一步在验什么 |
|---|---|---|---|
| 1 | `AT` | `OK` | 通路是否活着 |
| 2 | `AT+SN?` | `+SN:"VWA2608A0013"` 后跟一行 `OK` | 介质空白时回的是 `app_config.h` 的默认值 |
| 3 | `AT+CFG?` | `+CFG:1,1,0,0,0,0,0,0` 后跟一行 `OK` | 第 2 位 `present=1` = **NOR 探测成功**（JEDEC `EF 40 16`）；第 3 位 `loaded=0` = 介质上没有有效记录，用的还是默认值 |
| 4 | `AT+SN="VWA2608A0020"` | 先 `OK`，随后日志 **`store: saved ver=1 seq=1 gen=… offset=0x… N B`**；**值变了会接着出现 `system: rebooting now, src=identity`**，设备自动重启 | **`OK` 只代表「已受理」，落盘证据是那行 `saved`**（`gen` = 扇区代次、`offset` = 该记录在 CONFIG 分区内的偏移）；重启是「身份写成功」的正常现象。⚠ 写入值**不能等于**出厂默认值 `APP_CFG_BLE_SN`，否则被判「产线还没刷」而拒写（`+CME ERROR:2`） |
| 5 | `AT+VER?` | `+VER:"<版本>","<编译日期>"` 后跟一行 `OK` | 固件是不是当前这份（版本与横幅同源） |
| 6 | 断电 3 秒再上电 → `AT+SN?`、`AT+CFG?` | `+SN:"VWA2608A0020"` / `loaded=1 ver=1` | **这一步才是「掉电保存」的验收**（第 4 步的自动重启已经顺带验过一次） |
| 7 | `AT+TRANSINTVL?` | `+TRANSINTVL:20` 后跟一行 `OK` | 数值型参数**不带引号**；出厂默认 20 分钟 |
| 8 | `AT+TRANSINTVL=?` | `+TRANSINTVL:(1,20)` 后跟一行 `OK` | 数值型报的是**范围**，不是字符数 |
| 9 | `AT+TRANSINTVL=5` → `AT+TRANSINTVL?` | 先 `OK`，再读到 `+TRANSINTVL:5`；随后日志 `store: saved ver=… seq=…` | 改完立即生效 + 异步落盘 |
| 10 | `AT+TRANSINTVL=0`（或 `=21`） | `+CME ERROR:2`，且 `AT+TRANSINTVL?` 仍是上一个值 | 越界**不写进影子**（写进去会污染介质上那份记录） |
| 11 | 断电 3 秒再上电 → `AT+TRANSINTVL?` | 仍是第 9 步写入的值 | 业务参数的掉电保持 |
| 12 | `AT+SN="bad/id"`（含 `/`） | `+CME ERROR:2`，且 `AT+SN?` 不变 | 非法字符会破坏 MQTT 主题，**必须拒写**（写下就静默失效） |
| 13 | 板子仍是出厂默认 SN 时上电 | 横幅后出现 `modem: device SN unusable (len=…) -> 4G disabled; …`，且**没有** `cloud link ready` | 「未配置就不上网」是设计，不是故障（防同身份互踢） |
| 14 | 刷上合法 SN 后 → `AT+MQTTSUBACK` 里的主题串 | `sensor-product/<你刷的 SN>/command`（4 段、不带前导 `/`） | **这一步确认 `deviceId` 真的取自 SN**，且与平台侧配置逐字一致 |
| 15 | `AT+BLESVCUUID?` | `+BLESVCUUID:"CDAB0000-1234-5678-1234-56789ABCDEF0"` 后跟一行 `OK` | 回显名必须是 `+BLESVCUUID:`（平台按它匹配），不是 `+UUID:`；同一份值用 `AT+UUID?` 也能读到 |
| 16 | `AT+UUID="<新值>"`（串口） | `OK` → `store: saved` → **`system: rebooting now, src=identity`**（值变了才重启） | UUID 是身份类：**只允许串口写**、写成功自动重启（它只在上电时写进 VG6328） |

### 判读要点

> [!important] 「存储是不是好的」要分三层验，只验一层会误判
> | 层次 | 看什么 | 好的样子 | 坏的样子 |
> |---|---|---|---|
> | ① **硬件通路**（芯片在不在、SPI 通不通） | `AT+CFG?` 第 2 位 `present`；启动横幅 | `present=1`（JEDEC `EF 40 16` 探到了） | `present=0`，或横幅 `store: flash load failed (…)` |
> | ② **读得回来**（掉电后值还在） | `AT+CFG?` 第 3 位 `loaded`、第 5 位 `ver`；启动横幅 | `loaded=1`，横幅是 `store: loaded ver=… gen=…`（**不是** `blank flash`） | `loaded=0`（说明用的是编译期默认值） |
> | ③ **写得进去**（能落盘） | 写一次参数后的日志 + `AT+CFG?` 第 7/8 位 | 出现 `store: saved ver=… seq=… gen=… offset=0x… N B`，`ok` 计数 +1、`fail` 不变 | `store: save failed (…)` / `store: save rejected (…)`，`fail` +1 |
>
> **① 过、③ 不过**是最容易被误判成「驱动写错了」的一种：**`/WP`(pin3) 或 `/HOLD`(pin7) 悬空**时，
> 探测与读取全都正常，只有编程/擦除**静默失败**（`WEL` 照样置位）。
> 另外**只验 ①②（读得到）而没写过，等于没验 ③** —— 空白芯片本来就没有记录可读。

- **`OK` 只是「已受理」**：写参数是先改内存影子、再由 `AO_Store` 异步落盘。完整的落盘证据是
  `store: saved ver=… seq=… slot=…`，以及 `AT+CFG?` 里 `dirty` 回到 `0`。
- **`seq` 递增、`offset` 轮换**：每次成功保存 `seq` 都 +1（`AT+CFG?` 第 6 位），而 `offset` 在
  CONFIG 分区的 **8 个扇区**之间轮换（`APP_CFG_CONFIG_JOURNAL_SIZE = 0x8000` ÷ 4 KiB）。
  它的意义是「写到一半掉电时**另一个扇区**的旧记录仍然完好」——这就是换了 NOR 之后取代
  A/B 双槽的机制。看到 `offset` 不再前进，说明轮换逻辑坏了。
  磨损上限 ≈ 10 万次 × 8 扇区 = 约 **80 万次**保存。
- **`ver` 只增不减**：`AT&F` 也是一次变更，会让它继续自增，不会倒回 0。
- **`AT+I2C?` 是异步的**：先立刻回 `OK`，约 0.3 s 后逐条打出 `+I2C:<7 位地址>`（最多 8 条），
  最后以 `+I2C:END` 收尾，另有一条人类可读的 `store: i2c scan done, N device(s)`。
  **注意它只是 I2C 总线诊断，与参数介质无关**（参数现在存在 SPI NOR 上）；
  扫到什么取决于板上是否还装着 AT24C04。
- **`pin` 是凭据（明文）**：测试记录、截图、工单里都不要带上它的值
  （[[AGENTS#4.2 其他工作区规则]] 的凭据纪律）。`at_smoke.ps1` 对 `AT+PIN?` 只校验格式、不打印值。
- **写参数要说清生效范围**：`AT+SN="…"` 立刻对后续读取生效，且它有**三个**用途：
  ① MQTT `clientId` 与 10 条主题里的 `deviceId`；② 蓝牙认证应答里的 `sn` 字段
  （`ble_protocol.c` 读的是参数影子的地址，改完立即生效）；③ **蓝牙广播名**——
  `ble.c` 把 `local_name` 也指向 `SVC_PARAM_BLE_SN`，由 VG6328 的 `AT+NAM=` 在启动配置时写进模组。
  ③ 只在**上电配置时**写一次，所以改完要重启才在广播里生效；而写 `SN` 会自动重启（见下条），
  两者正好闭环——**产线只需一条 `AT+SN=`，不必再单独刷广播名**。
  相比之下 `UUID` / `ULEN` 也是**启动时一次性写进模组**的，改了要重启才生效。
- **`SN` 写成功会自动重启**（值变了才会）：这是「身份参数」的统一规矩，不是故障。
  因为 `SN` 就是 `deviceId`（MQTT `clientId` + 10 条主题都是启动时拼的），
  **不重启就不会用新身份重新订阅**；重启前 `AO_System` 还会等参数落盘，避免"重启回来还是旧值"。
  `UUID` 同理（它只在上电时写进 VG6328，不重启广播里还是旧的）。
- **`AT+BLESVCUUID?` 是 `AT+UUID?` 的"带名字"版本**：读的是同一个值，但**回显名跟着命令走**
  （`+BLESVCUUID:"…"`），因为平台侧是按 `^\+BLESVCUUID:[^\r\n]*\r\nOK\r\n$` 匹配的。
  写入仍然只有 `AT+UUID="…"` 一种写法，而且**只允许串口**。
- **未刷 `SN` 的设备不会连 4G**：串口会打 `modem: device SN unusable reason=… pos=… ch=0x… len=… -> 4G disabled; …`，
  用 `AT+SN="<设备号>"` 刷一个合法值即可（会自动重启并上线）。这不是故障，是防"同身份互踢"。

### 常见现象对照

| 现象 | 多半是 |
|---|---|
| 完全没有响应 | 串口被别的程序占用 / 波特率不是 115200 / `PA9`-`PA10` 接反 / 板子没跑起来 |
| 回 `ERROR` | 命令拼错或没带行尾；写法不在 `AT`、`AT+<名>?`、`AT+<名>="<值>"`、`AT+<名>=?`、`AT+CFG?`、`AT+VER?`、`AT+CMD?`、`AT&F`、`AT+I2C?`、`AT+RST` / `AT+REBOOT` 之内 |
| 发了旧写法（`sn?`、`cfg!`）回 `ERROR` | **预期行为**：2026-09-27 起只认标准 AT 写法，旧语法不兼容 |
| `+CME ERROR:1` | 参数名不在 7 个之列（`SN` `PIN` `UUID` `DEVNAME` `MODEL` `BATCH` `TRANSINTVL`），或用了**退役的 `NAME`**（广播名就是 `SN`，改用 `AT+SN?`） |
| `AT+TRANSINTVL=…` 回 `+CME ERROR:2` | 值不是纯十进制数字，或不在 1~20 之内（分钟） |
| `+CME ERROR:3` | 上电后约 100 ms 内就发了写命令（启动加载还没结束），稍等再试 |
| `+CME ERROR:4` | **从云端写了 `AT+SN="…"`**：身份类参数只允许串口写（产线入口），云端只能 `AT+SN?` 读 |
| `AT+SN="…"` 回了 `OK` 却不见 `saved` | 落盘失败：往前找 `store: save failed (…), dirty retained, retry=…`；若连装载行都没有，见下面 `present=0` 那行 |
| `AT+CFG?` 里第 2 位（`present`）为 0 | NOR 探测失败：查 `PA5`/`PA6`/`PA7`/`PA8` 接线与片选，**`/WP`(pin3) 与 `/HOLD`(pin7) 必须拉到 3.3 V**（悬空时"读正常、写静默失败"，`present` 仍可能是 1） |
| 开机日志的波特率与预期不符 | 说明宏没生效——启动横幅打的是**外设里的实际值**，见 [[03-资源分配#引脚分配]] |

## 边界行为

| 场景 | 行为 |
|---|---|
| RX 环形缓冲写满 | 丢弃新字节，不阻塞中断 |
| Node 事件队列满 | 投递不触发断言；后续接收事件可继续触发抽干 |
| AT 行超过上限（64） | 超出的字符被丢弃，整行按截断内容解析（解析器内部也会清行）；结果是回一条 `ERROR` |
| TX 日志队列写满 | 按配置丢弃并累计丢弃字节数 |
| EEPROM 不存在 / 总线不通 | 探测失败后回落到编译期默认值；写参数只改内存并回 `OK`，日志给 `save failed` |
| 写 EEPROM 失败 | 重试 → 补时钟恢复总线 → 再失败则保留内存值、`dirty` 清零、打一条 `save failed` |
| 产品级同步、寻址、确认、重传 | 尚未实现 |

## 电池电压属性（2026-10-12）

4G可选`battery_voltage`为数值V、三位小数，如`3.670`；BLE `voltage`为整数mV，如3670。二者来自同一批电池测量，电池无效均在data报告中省略相应字段；平台物模型仍需登记同名属性。
电池与SCL3300由请求式批次一起采集：BLE `sample_interval`与`AT+TRANSINTVL`共用1..20分钟持久参数。按键、认证首采、4G上线及统一周期到期均触发同批采集和云端上传，已认证BLE同步发送。BLE设置示例`{"cmd":"set","param":"sample_interval","v":2}`表示2分钟，成功后串口`AT+TRANSINTVL?`应回`+TRANSINTVL:2`；BLE params返回单位`min`。当前不再有每秒调试采样行，也不发布固定3300mV占位。
失败诊断为`battery: sample failed reason=<标签> adc=<状态>`或`battery: start failed`；诊断API仍可在调试器查看raw/vref/vdda等，但正常运行不逐次打印原始值。验证见[[05-任务说明#PB15 按键触发一次上报]]与`battery_test.ps1`。

## 按键触发上报日志（2026-10-12）

PB15稳定按下输出`button: pressed`，并请求新采样和120s广播窗口。`modem: report requested/queued`只表示待发/交付组件，只有`cloud> sent {...}`表示模组已确认该次发布成功；订阅端接收仍需单独核对。窗口请求日志`ble: advertising window requested, duration=120000 ms`也不代表AT已成功，异常由模组失败原因诊断。
云端主题和属性格式保持不变，当前主题前导斜杠以`app_config.h`各独立前缀宏为准，现场订阅`/sensor-product/<SN>/properties/report`。
