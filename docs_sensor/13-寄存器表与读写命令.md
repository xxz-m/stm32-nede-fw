# 4G 云平台对接协议

本文定义倾角监测设备与云平台之间的 MQTT 通道、基础指令、寄存器读写、数据上报及断网补传规则，供云平台开发、设备端开发和接口联调使用。

平台接入分为两条业务路径：

- **控制与查询**：平台通过 MQTT 下发 `AT`、`AT+RST`、`AT+READ`、`AT+WRITE`，设备返回关联应答；零点标定使用独立的重要操作命令 `AT+ZERO="CONFIRM"`。
- **数据上报**：设备主动发布包含 `deviceId`、`timestamp` 和 `properties` 的 JSON；正常上报与历史补传使用相同格式。

所有示例中的产品标识、设备编号和测量值均为演示值。服务器地址、产品标识和连接鉴权信息由项目接入配置提供。

## 一、通信通道与命令

### 1.1 MQTT 主题

`deviceId` 为整机 SN，与 MQTT `clientId`、主题中的设备编号一致，区分大小写。SN 最多 23 个 ASCII 字符，允许字母、数字、`-`、`_`、`.`。

| 用途 | 主题模板 | 方向 | QoS |
|---|---|---|---|
| 数据上报 | `/<productId>/<deviceId>/properties/report` | 设备 → 平台 | 0 |
| 命令下发 | `/<productId>/<deviceId>/command` | 平台 → 设备 | 1 |
| 命令应答 | `/<productId>/<deviceId>/command/reply` | 设备 → 平台 | 1 |

三条主题均包含前导 `/`，平台的发布主题、订阅模板和回复过滤器必须逐字一致。示例：

```text
/example-product/NODE0001/properties/report
/example-product/NODE0001/command
/example-product/NODE0001/command/reply
```

> [!important] 设备**只订阅 `command` 一条**（2026-10-14，`#139`）
> 设备端订阅集合已收敛为 `/<productId>/<deviceId>/command`；**平台的下行指令必须发到这条主题**，
> 发到其它主题（如 `properties/write`、`function/invoke`、`state-check`）设备收不到——现场实测
> 订阅到第二条主题时 broker 会直接掐断连接（后续所有订阅与发布都回 `+CME ERROR:8002`）。
> 开关：`APP_CFG_MODEM_TOPIC_SUBSCRIBE_COMMAND_ONLY`。

### 1.2 命令请求与关联应答

平台下发：

```json
{"id":"cmd-001","command":"AT"}
```

设备成功应答：

```json
{"id":"cmd-001","command":"AT","data":"OK\r\n"}
```

寄存器读写请求 CRC 校验失败时的应答：

```json
{"id":"cmd-register-002","data":"+CME ERROR:6"}
```

- `id` 由平台生成，同一请求及其重试使用同一个关联 ID；设备原样回显，用于匹配应答。长度不超过 63 个 ASCII 字符。零点标定不得自动重试，按 §1.3.1 的重要操作规则处理。
- `command` 只保存命令类型：读为 `AT+READ`，写为 `AT+WRITE`，不得拼接等号、地址、数值或 CRC。`AT`、`AT+RST`、`AT+ZERO="CONFIRM"` 保持原命令形式，请求不带 `data`；命令中的引号按 JSON 规则转义。
- 读写请求的 `data` 为逗号分隔的参数字符串，包含地址、写入值（仅读取时省略）和末尾 CRC，不包含 AT 前缀、等号或额外的引号。读写应答仅携带 `id`、`data`，回显请求的 `id`；`data` 保存地址、结果及 CRC，不携带命令前缀或结果行。JSON 中的换行、引号和反斜杠按标准转义。
- 命令报文使用 `id`、`command`、`data` 三个字段；上述无参数请求省略 `data`。应答不使用 `ok` 或独立 `error` 字段，读写成功或失败由 `data` 内的逐地址结果判断；帧级错误使用错误文本。

### 1.3 基础 AT 指令【必须保留的三项】

| 指令 | 功能 | 成功应答 | 平台处理 |
|---|---|---|---|
| `AT` | 握手 | `OK\r\n` | 确认设备命令通道可响应 |
| `AT+RST` | 重启整机 | `OK\r\n` | 应答表示重启请求已受理，随后观察设备重新上线 |
| `AT+ZERO="CONFIRM"` | 零点标定 | `OK\r\n` | 仅在新零点已保存并生效后返回成功，按 §1.3.1 人工确认后下发 |

基础指令为以上三条，不附加 CRC。信息查询和配置统一通过寄存器命令完成。

### 1.3.1 零点标定（重要操作）

零点标定用于将设备**当前安装姿态设为三轴倾角的零点**，属于改变测量基准的重要操作，仅在安装调试或经确认需要重新建立基准时使用。SCL3300 已有工厂校准，本命令进行整机安装后的零点偏置修正。

| 项目 | 约定 |
|---|---|
| 命令 | `AT+ZERO="CONFIRM"`，大小写及确认字串必须完全一致 |
| 执行前提 | 设备已固定在人工确认的基准姿态，保持静止，采样有效且稳定 |
| 标定对象 | 同时更新 X / Y / Z 三轴倾角零点；不修改三轴加速度、温度及电池电压 |
| 生效范围 | 成功后的倾角寄存器 `0x10`–`0x12` 及上报 `angle_x/y/z` 使用新零点 |
| 掉电保持 | 三轴零点一起保存，重启和断电后保持；再次成功标定时整组替换 |
| 成功应答 | `OK\r\n`，表示新零点已保存并生效，不能只表示请求已受理 |
| 失败应答 | `ERROR\r\n`，保持原零点，不允许只更新部分轴 |
| CRC | 本命令及其结果行不附寄存器 CRC |

标定应采集新的有效稳定数据，以**未扣零点的倾角值**建立新偏置，不能用旧样本或已归零后的显示值继续累加。标定后保持原姿态，三轴倾角应在噪声及测量精度允许范围内接近 0°。失败、忙、运动不稳定、传感器异常或存储失败时均不得替换原有效零点。未带确认字串的 `AT+ZERO` 及其他字串均拒绝执行。

**平台下发要求：**

- 只向具有标定权限的运维人员开放单台设备操作，展示目标 SN 和“将当前姿态设为新零点、影响后续倾角基准”的提示，人工二次确认后下发。
- 禁止平台在开机、上线、重连、定时任务、批量任务或告警处理中自动调用。确认字串用于防止误触，不替代平台权限校验。
- 每次人工标定生成新的 `id`。设备按标定 `id` 去重，重复投递返回已记录结果，不再次采集标定；成功关联 ID 及结果随零点一起掉电保存。
- 应答超时或连接中断时，平台显示“结果未知”，不得自动重发或以新 ID 重试。先由人员核对操作结果及当前姿态，再决定后续处理。
- 平台记录操作者、设备 SN、关联 ID、操作时间和结果，在历史曲线上标记测量基准变更。标定前已保存的记录及其补传值保持原样，不按新零点重新换算。

联调验证：人工确认固定姿态后发送第三节的标定请求，成功后读 `0x10`–`0x12` 并核对上报倾角接近 0°，重启后再次核对；对同一 `id` 的重复投递不得重新标定。无确认字串、无效/不稳定采样及存储失败应返回失败并保持原基准；核对标定前积压记录补传值不变。

### 1.4 寄存器读写格式（指令类型写在 `command`，参数写在 `data`）

| 操作 | 请求 command | 请求 data | 应答 data 主体 |
|---|---|---|---|
| 读 | `AT+READ` | `<地址>,<地址>,…,<CRC>` | `<地址>,<数据或标记>,…,<CRC>` |
| 写 | `AT+WRITE` | `<地址>,<数据>,…,<CRC>` | `<地址>,<状态码>,…,<CRC>` |

- 地址固定为 **2 位大写 hex**，写入数据及正常读出数据固定为 **4 位大写 hex**；读取失败时该项使用两个字母的固定标记 `XX` / `XY`。写入结果为两字符状态码：`00` 表示成功，错误使用 `XY`、`RO` 等两个大写字母，详见第四节；帧内不加 `0x`。
- 请求和应答的 `data` 内只用半角逗号分隔，不允许空格。
- 应答带地址，顺序与请求一致，重复地址也逐项返回。
- 读应答的 `data` 按请求顺序逐项返回地址及结果：正常值为四位 hex，`XX` 表示该地址没有可用数据，`XY` 表示地址不存在。批量读取允许正常数据与标记同时出现，详见 §4.3。
- 写入按请求顺序处理；同一地址多次合法写入时，后写值生效。某一项失败不回滚其他成功项，无效写入不覆盖已生效值。
- 一次最多读 **16 个地址**、写 **6 对地址/数据**。满额读请求的 `data` 为 52 字符，满额写请求的 `data` 为 52 字符，不含 JSON 外壳。
- 16 地址读应答的 `data` 最长为 132 个 ASCII 字符（全部项为正常四位数据），不含 JSON 外壳；平台应答缓冲不能按请求长度配置。
- 每条读写应答将地址、结果及 CRC 直接放入 `data`，不添加 AT 前缀、引号包装、CR/LF 或最终结果行。
- 读请求全部为正常数据时表示成功；任一项为 `XX` / `XY` 时表示该项失败。无论是否含标记，读写应答都按实际 `data` 负载计算 CRC，标记字母也参与计算。

### 1.5 CRC 算法、公式与显示顺序

| 项目 | 约定 |
|---|---|
| 算法 | CRC-16/MODBUS |
| 生成多项式 | `G(x) = x^16 + x^15 + x^2 + 1`，常规表示 `0x8005`，反射表示 `0xA001` |
| 初值 | `0xFFFF` |
| 处理顺序 | 每字节最低位先处理 |
| 最终异或 | 无 |
| 输入 | JSON `data` 字符串中、最后 `,CRC` 之前的 ASCII 原文 |
| 排除内容 | JSON 外壳、`id`、`command`、字符串引号、最后的逗号与 CRC 字段 |
| 显示 | 4 位大写 hex，CRC 低字节在前 |
| 校验方向 | 设备校验请求；平台校验读写应答 |
| 例外 | `ERROR` / `+CME ERROR:n` 不附加 CRC |

令 `C = 0xFFFF`。对每个 ASCII 字节 `b`，先做 `C = C XOR b`，再重复 8 次下列二选一操作：

```text
若移位前 (C AND 1) = 1：C = (C >> 1) XOR 0xA001
否则：                  C = C >> 1
```

最终 CRC 文本为 `HEX2(C AND 0xFF) + HEX2((C >> 8) AND 0xFF)`，其中 `+` 表示字符串拼接。

例如 `01,0005` 的 ASCII 字节为 `30 31 2C 30 30 30 35`，CRC 数值是 `0xFC65`，线上写作 `65FC`。

**数据字段与 CRC 的顺序不同**：数据 `0032` 表示数值 50；CRC `65FC` 表示校验值 `0xFC65`。CRC 对 ASCII 文本计算，不先将地址或数据转成二进制数。参考代码见附录。

### 1.6 数据解释

数值寄存器均为 16 位值，符号、单位和缩放由寄存器表定义。有符号数采用二进制补码，例如 `FC18` 表示 −1000。

字符串每格存两个 ASCII 字符，先高字节、后低字节。例如 `4E4F` 解码为 `NO`。SN 以 `00` 结束并补零；UUID 末段固定 12 字符，无结束符。

## 二、倾角仪寄存器表

| 地址区间 | 用途 |
|---|---|
| `0x01`–`0x0F` | 可读写配置区，掉电保持 |
| `0x10`–`0x1F` | 只读测量区 |
| `0x20`–`0x2F` | 只读设备信息区 |
| `0x30`–`0x3F` | 状态区预留 |
| `0x40` 起 | 只读字符串区 |

| 地址 | 名称 | 类型 | 读写 | 缩放 | 单位 | 范围 / 编码 | 默认 | 掉电保持 |
|---|---|---|---|---|---|---|---|---|
| `0x01` | 上报周期 `transintvl` | u16 | RW | ×1 | 分钟 | 1–20 | 20 | 是 |
| `0x02` | 测量模式 `measurement_mode` | u16 | RW | ×1 | — | 1–4 | 3 | 是 |
| `0x03` | 上传选择 `report_mask` | u16 | RW | 位掩码 | — | `0001`–`000F` | `000F` | 是 |
| `0x10` | X 倾角 `angle_x` | s16 | RO | ÷100 | ° | −18000…18000 | — | 否 |
| `0x11` | Y 倾角 `angle_y` | s16 | RO | ÷100 | ° | 同上 | — | 否 |
| `0x12` | Z 倾角 `angle_z` | s16 | RO | ÷100 | ° | 同上 | — | 否 |
| `0x13` | 片内温度 `temperature` | s16 | RO | ÷100 | ℃ | 16 位有符号编码 | — | 否 |
| `0x14` | 电池电压 `battery_voltage` | u16 | RO | ×1 | mV | 0…65535（编码范围） | — | 否 |
| `0x15` | X 加速度 `acc_x` | s16 | RO | ×1 | mg | −32768…32767（编码范围） | — | 否 |
| `0x16` | Y 加速度 `acc_y` | s16 | RO | ×1 | mg | 同上 | — | 否 |
| `0x17` | Z 加速度 `acc_z` | s16 | RO | ×1 | mg | 同上 | — | 否 |
| `0x20` | 固件版本 | u16 | RO | 主×100+次 | — | `0066` = v1.02 | — | 否 |
| `0x40`–`0x4B` | 整机 SN `sn` | ASCII（12×u16） | RO | — | — | 最多 23 字符，结尾补 `00` | 设备值 | 是 |
| `0x50`–`0x55` | UUID 末段 `uuid` | ASCII（6×u16） | RO | — | — | 固定 12 个十六进制字符 | 设备值 | 是 |

RO 表示平台只读，RW 表示平台可读写。未分配地址不作为有效寄存器。表中编码范围不代表传感器精度或硬件实际有效量程。

一次读取多个测量地址时，正常数据应来自同一批已完成采样，避免三轴或温度跨批拼接。某地址尚无有效测量值时不得用 0 或旧故障值冒充有效数据，该项返回 §4.3 定义的 `XX` 标记，不影响其他地址逐项返回。

固件版本先按十进制计算 `主×100+次`，再转 4 位 hex：v1.02 → 102 → `0066`。

### 2.1 测量模式与加速度

`0001`、`0002`、`0003`、`0004` 分别对应 SCL3300 的 Mode 1–4。模式影响传感器灵敏度和带宽，不改变上报周期。非法模式值写入返回逐地址状态码 `OV`。

加速度单位为 mg，`1000 mg = 1 g`；`03E8` 为 +1000 mg，`FC18` 为 −1000 mg。

平台写入配置后，可通过 `AT+READ` 读回核对。配置参数应满足掉电保持要求，联调时以重启后读回值验证。

### 2.2 SN / UUID 字符串读取

- SN 为整机编号，也是 `deviceId`。按地址升序拼接 12 格的高/低字节，遇到第一个 `00` 结束。
- UUID 的固定前缀是 `CDAB0000-1234-5678-1234-`，所有设备相同，不随报文重复传输。
- 一次读取 `0x50`–`0x55` 六格，得到 12 个 ASCII 字符，再追加到固定前缀后。
- 示例末段 `56789ABCDEF0` 还原为 `CDAB0000-1234-5678-1234-56789ABCDEF0`。
- UUID 六格无 `00` 结束符，必须一次收齐；`0x56`–`0x63` 不属于 UUID。
- 向 SN / UUID 任一地址写入，返回逐地址状态码 `RO`。

### 2.3 上传参数选择

`0x03` 的低四位分别控制四类数据，允许按位或组合：

| 位 | 掩码 | 类别 | 对应上报字段 |
|---|---|---|---|
| bit0 | `0001` | 信号与位置 | `signal_quality`、可取得的 `cell_tac` / `cell_id`、有效定位的 `location_lon` / `location_lat` |
| bit1 | `0002` | 三轴加速度 | `acc_x` / `acc_y` / `acc_z` |
| bit2 | `0004` | 三轴倾角 | `angle_x` / `angle_y` / `angle_z` |
| bit3 | `0008` | 温度与电池 | `temperature`，电池采样有效时的 `battery_voltage` |
| bit4–bit15 | — | 保留 | 必须为 0 |

- 默认 `000F`，四类全选；`000C` 为倾角＋温度/电池；`000D` 再增加信号与位置。
- 至少选择一类，`0000` 和保留位非零均返回逐地址状态码 `OV`，原配置保持。
- 未选择类别的字段省略，不发送 0 占位；未取得的小区、定位或无效电压同样省略。
- `deviceId` 和 `timestamp` 每条上报都携带，不受类别选择影响。
- 该参数只控制上传字段，寄存器读取不受限制；历史记录按采样时保存的类别选择生成补传内容。

## 三、命令交互示例

下列 CRC 均为**实算值**（Modbus CRC16，仅覆盖 `data` 内负载，不含末尾的 `,CRC`，低字节在前）。

校验方法：取 JSON `data` 字符串最后一个逗号之前的内容（不含 JSON 外壳、字符串引号、最后的逗号和 CRC 字段），按 ASCII 算 CRC16；将结果按低字节在前排列，写成 4 位大写 hex。

以下请求和应答均为 JSON 报文，箭头行仅作说明，不随报文发送。读写请求携带 `id`、`command`、`data`，应答仅携带 `id`、`data`，应答 `id` 与请求一致。读写应答的 `data` 仅包含地址、结果及 CRC，不包含 `+READ` / `+WRITE` 前缀、CR/LF 或 `OK` / `ERROR` 结果行；仅帧级错误允许返回错误文本。零点标定保持原格式。

### 例 1：写上报周期 = 5 分钟


```arduino
请求   {"id":"cmd-register-001","command":"AT+WRITE","data":"01,0005,65FC"}
                    ↑ 0x01 地址、0x0005 = 5 分钟
                    ↑ CRC 覆盖 "01,0005" = 0xFC65 → 低字节在前 = 65FC
应答   {"id":"cmd-register-001","data":"01,00,BF25"}
                    ↑ 地址 0x01 → 状态码 00 = 成功
                    ↑ CRC 覆盖 "01,00" = 0x25BF → 低字节在前 = BF25
```

### 例 2：设置测量模式 = Mode 4


```arduino
请求   {"id":"cmd-register-002","command":"AT+WRITE","data":"02,0004,A40F"}
                    ↑ 0x02 地址、0x0004 = Mode 4
                    ↑ CRC 覆盖 "02,0004" = 0x0FA4 → 低字节在前 = A40F
应答   {"id":"cmd-register-002","data":"02,00,BF61"}
                    ↑ 地址 0x02 → 状态码 00 = 成功
                    ↑ CRC 覆盖 "02,00" = 0x61BF → 低字节在前 = BF61
```

### 例 3：选择信号、倾角、温度与电池


```arduino
请求   {"id":"cmd-register-003","command":"AT+WRITE","data":"03,000D,A43A"}
                    ↑ 0x03 地址、0x000D = 信号/位置＋倾角＋温度/电池，不上传加速度
                    ↑ CRC 覆盖 "03,000D" = 0x3AA4 → 低字节在前 = A43A
应答   {"id":"cmd-register-003","data":"03,00,BE9D"}
                    ↑ 地址 0x03 → 状态码 00 = 成功
```

## 四、错误码

**正常值与标记分开解释**：读应答 `data` 的每项结果为四位大写 hex 数据，或固定字面标记 `XX` / `XY`；写应答 `data` 的每项结果为两字符状态码，`00` 表示成功，错误使用两个大写字母。字母错误标记均含非十六进制字符，不会与正常数据重叠；`00` 仅按写入结果解释。`+CME ERROR:n` 仅用于格式或 CRC 等帧级错误。

### 4.1 逐地址写入结果

| 状态码 | 含义 | 平台处理 |
|---|---|---|
| `00` | 该地址写入成功 | 可读回核对 |
| `XY` | 地址不存在，读写统一使用此标记 | 核对寄存器地址 |
| `RO` | 地址只读 | 停止向该地址写入 |
| `OV` | 数值越界或选择组合非法 | 按范围/掩码修正 |
| `IC` | 数据含非法字符 | 使用 4 位大写 hex |
| `NP` | 该地址不允许云端写入 | 按权限处理 |
| `SE` | 参数存储未就绪或写入被拒 | 保留原值，按设备状态重试 |
| `NR` | 地址不属于数据寄存器 | 核对指令用途 |

批量写入允许部分成功，平台按地址分别显示结果。所有项为 `00` 时表示全部成功；任一项不是 `00` 时表示该项失败，成功项仍然有效。`data` 不追加 `OK` / `ERROR` 或换行。

成功状态是两个 ASCII 字符 `00`，错误状态是两个大写 ASCII 字母，均为实际发送的固定值，必须逐字匹配表中值。除读写共用的 `XY` 外，本表状态码用于写应答的 `data`；读取的 `XX` 仍表示没有可用数据。正常读取值 `0002` 仍是数据，不作为状态解析。

### 4.2 帧级错误

| 应答 `data` 中的错误文本 | 含义 |
|---|---|
| `+CME ERROR:6` | CRC 校验失败 |
| `+CME ERROR:2` | 地址列表为空、字段数量/宽度错误或结构不合法 |
| `ERROR` | 命令不成形、超长或无法识别 |

帧级错误不附 CRC，不执行写入。四位数据中含非 hex 字符时，可在结构与 CRC 校验后返回逐地址 `IC`；字段宽度或地址结构错误使用帧级错误。

### 4.3 读取失败与数据区分

请求的格式和 CRC 校验通过后，读应答的 `data` 按“地址、结果”逐项返回：

| 项结果 | 含义 | 平台处理 |
|---|---|---|
| 四位大写 hex，如 `0002` | 正常寄存器数据 | 按该地址的类型、缩放和单位解码 |
| `XX` | 地址存在，但没有可用数据 | 记录该项不可用，保留已有历史值，不入库为测量值 |
| `XY` | 地址不存在 | 记录该项地址错误，核对寄存器表 |

- `XX`、`XY` 是线上实际发送的两个 ASCII 字符，不是待替换的占位符；平台先匹配这两个标记，再按四位 hex 解析正常值。其他长度或字符组合视为应答格式错误。
- “没有可用数据”包括尚未取得有效样本、当前测量无效或无法可靠读取请求值；不得改用默认 0、数值错误号或故障前旧值冒充本次有效数据。
- 批量读取允许**逐项成功或失败**，每个请求地址都返回一项，地址、顺序和数量保持一致。平台必须先校验整帧 CRC 和结构，再使用其中的正常数据。
- 全部项为正常值表示全部成功；任一项为 `XX` / `XY` 表示该项失败，仍保留完整的逐项结果和 CRC，不追加结果行或换行。正常项可独立使用，异常项不能用 0 替代。
- 含标记的应答也必须计算 CRC，`X` / `Y` 按 ASCII 原文参与计算。例如 `10,XX` 的 CRC 为 `AD37`，`10,0002,FF,XY` 的 CRC 为 `717B`；不能沿用替换前数据的 CRC。
- `0000`、`0001`、`0002`、`FFFF` 等不作为通用读错误标记：它们是否有效由对应寄存器的类型和范围决定。比如倾角数据 `0002` 是 0.02°，加速度数据 `FFFF` 是 −1 mg。
- `+CME ERROR:n` 继续用于 §4.2 的帧级错误，此时 `data` 保存错误文本，不含可解析的逐项结果或寄存器 CRC。CRC 错误和未知应答格式都不得作为有效测量入库。

联调验证：对 `{"id":"cmd-read-check","command":"AT+READ","data":"10,1434"}` 分别检查真实数据 `0002` 和无可用数据标记 `XX`，确认平台不会混淆；再用 `{"id":"cmd-read-check","command":"AT+READ","data":"10,FF,249F"}` 验证 `0x10` 正常值与 `0xFF` 的 `XY` 同时返回，CRC 包含标记，整体失败不影响正常项解码。

## 五、断网存储、恢复补传与时间基准

### 5.1 正常上报与一分钟补传

正常周期由 `0x01` 配置，默认 20 分钟。每次有效采样及其原采样时间保存在设备的掉电保持存储中，网络恢复后可以继续补传。

| 场景 | 采样与保存 | 发送规则 |
|---|---|---|
| 正常联网、无积压 | 按正常周期采样并保存 | 按正常周期上报 |
| 意外断网 | 正常周期继续，记录追加保存 | 等待网络恢复 |
| 网络恢复、有积压 | 正常采样继续，新记录追加队尾 | 每 60 秒补传最早一条未确认记录 |
| 历史队列清空 | 继续原正常采样时间表 | 恢复正常频率 |

- 网络恢复后的第一条历史记录在首个 60 秒补传时机发送，不额外插入上线新采样包。
- 同一时刻最多一条补传在途；未完成时不并发发起下一条。
- 补传失败保留原记录，后续补传时机继续处理；再次断网则暂停，恢复后续传。
- 补传期间的新采样进入同一队列，不另开并行发送通道。
- 补传只改变发送节奏，不把 20 分钟采样改成每分钟采样，也不改写 `0x01`。
- 平台应按记录的采样时间入库和绘图，支持历史乱序到达和重复接收。
- 设备清除已补传记录所依据的业务确认方式，以及平台幂等键，由设备端与平台在联调前共同约定。

### 5.2 时间语义

`timestamp` 是 **原采样时间**，采用 JSON 整数，单位为毫秒，表示自 `1970-01-01T00:00:00Z` 起经过的时间。设备在保存记录时写入时间戳，首次发送、重试、断电恢复后补传都保持同一个值，不能替换为发送时间或平台接收时间。

例如 `2026-10-13T12:20:00+08:00` 与 `2026-10-13T04:20:00Z` 是同一时刻，对应 `timestamp: 1791865200000`。时间戳按 UTC 基准计算，不额外加减 8 小时；平台展示时再转换当地时区。字段发送整数毫秒，不发送字符串、秒值或小数。

时间无效或无法解析的数据不能用接收时间冒充历史采样时间，应进入异常处理流程。时间异常的设备响应与平台处置方式在联调中对齐。

## 六、4G 数据发送示例

### 6.1 上报报文定义

正常上报和历史补传都发布到：

```text
/<productId>/<deviceId>/properties/report
```

| 顶层字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `deviceId` | string | 是 | 整机 SN，与主题设备编号一致 |
| `timestamp` | integer / ms | 是 | 原采样时间，UTC 基准的 Unix 毫秒时间戳 |
| `properties` | object | 是 | 本次记录的业务属性 |

`properties` 内所有测量值使用 JSON 数值，标识类字段使用字符串。上传 JSON 不附寄存器 CRC16。

| 属性 | 类型 / 单位 | 显示精度 / 规则 |
|---|---|---|
| `temperature` | number / ℃ | 片内温度，两位小数 |
| `angle_x` / `angle_y` / `angle_z` | number / ° | 两位小数 |
| `acc_x` / `acc_y` / `acc_z` | integer / mg | `1000 mg = 1 g` |
| `signal_quality` | integer | CSQ 0–31；99 表示未知 |
| `battery_voltage` | number / V | 三位小数；与寄存器 mV 相差 1000 倍 |
| `cell_tac` / `cell_id` | string | 蜂窝小区信息，十六进制文本 |
| `location_lon` / `location_lat` | number / ° | WGS-84，经纬度六位小数；定位有效时提供 |

属性是否出现由上传选择和数据有效性共同决定。平台必须接受可选属性缺失，不把缺失值解释为 0。

### 6.3 断网补传示例

示例日期为 2026-10-13，以下时刻均为 UTC+8。正常周期为 20 分钟，12:00 正常上报后断网，13:05 恢复网络：

| 实际发送时刻 | 报文的 `timestamp`                  | 说明             |
| ------ | --------------------------- | -------------- |
| 13:06  | `1791865200000` | 补传第一条历史记录      |
| 13:07  | `1791866400000` | 补传第二条历史记录      |
| 13:08  | `1791867600000` | 补传第三条历史记录，队列清空 |
| 13:20  | `1791868800000` | 按原正常周期上报       |

同一历史记录重试时，`deviceId`、`timestamp` 和测量值保持一致，平台不能用 13:06 等接收时刻替换 12:20 等采样时间。




## 附录：CRC 参考实现与平台自检

 参考实现

```c
#include <stddef.h>
#include <stdint.h>

/** @brief 对负载 ASCII 原文计算 CRC-16/MODBUS，不含末尾逗号和 CRC。 */
uint16_t crc16Modbus(unsigned char const *data, size_t length) {
    uint16_t crc = 0xFFFFU;
    size_t i;
    unsigned int bit;

    for (i = 0U; i < length; ++i) {
        crc = (uint16_t)(crc ^ data[i]);
        for (bit = 0U; bit < 8U; ++bit) {
            if ((crc & 1U) != 0U) {
                crc = (uint16_t)((crc >> 1U) ^ 0xA001U);
            } else {
                crc = (uint16_t)(crc >> 1U);
            }
        }
    }
    return crc;
}
```
